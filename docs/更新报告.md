## 四、关键设计决策

这一轮做出的、会影响后续所有工作的决策：

### 1. 领域层不依赖 Tauri

`yuhua-core` / `yuhua-fs` / `yuhua-store` / `yuhua-export` / `yuhua-stats`
是**纯 Rust 库**，不引入任何 Tauri 依赖。好处：

- 测试跑在毫秒级，不需要启动窗口
- 未来的 CLI 工具、批量导入脚本、迁移工具可以直接复用
- 「命令层是薄壳」这条架构约束变成**编译期保证**而非口头约定

### 2. 索引库必须放在工作区之外

已用测试钉死（`workspace_contains_no_binary_db`）。原因是 SQLite 带
WAL 与共享内存文件，云盘对正在写入的二进制做部分同步极易损坏；
而索引本来就是可抛弃的缓存。这条约束是「工作区可安全放进云盘」的前提。

### 3. 索引库用纯 Rust 实现中文分词（零 unsafe）

FTS5 自带的 `unicode61` 把中文整句当一个词，`trigram` 要求查询串至少
3 个字符 —— 两者对两字中文词（「羽化」「写作」「主角」，中文里最常见的形式）
都不可用。

方案是**写前预分词**：写入前用二元组切分并用空格连接，
再交给 `unicode61`（按空格切分）。效果与注册自定义分词器等价，
但分词逻辑成为**可完整测试的纯函数**，且全程零 unsafe ——
与工作区 `unsafe_code = "forbid"` 的约定一致。

### 4. 所有「危险操作」都有测试钉死边界

| 保证 | 对应测试 |
| --- | --- |
| 原子写不留半截文件 | `overwrites_existing_file_completely` |
| 临时文件与目标同目录（否则 rename 不原子） | `temp_file_is_in_same_directory` |
| 索引库不在工作区内 | `workspace_contains_no_binary_db` |
| 冲突副本只提示不删除 | `detect_never_modifies_files` |
| 恢复回收站不覆盖现有文件 | `restore_refuses_to_overwrite_existing_file` |
| 路径不能逃逸出工作区 | `resolve_rejects_parent_escape` |
| 统计合并幂等、不重复计数 | 合并算法的乱序 / 重复 / 冲突副本测试 |

### 5. 前端零 emoji、零外链、零图标字体

已用脚本**独立扫描核验**：全仓无 emoji 字符（唯一命中是 Rust 测试用例里
的 `★☆`，那是验证「原子写能处理任意 Unicode」的测试数据，不是界面装饰），
无外链资源，无图标字体。55 枚图标全部手写 SVG，55 个独立文件便于 tree-shaking。

## 四之二、代码审查发现并修复的缺陷（本轮新增）

对全仓做了一遍独立代码审查（读代码 + 实际探针验证，不是只看测试是否绿灯）。
审查确认了 **3 个未被现有测试覆盖的真实缺陷**，其中两处在导出链路，
一处对外 API 的健壮性缺口。三者均**已修复并补上回归测试**。

| # | 级别 | 缺陷 | 影响 | 修复位置 |
| --- | --- | --- | --- | --- |
| 1 | P1 | `escape_html` 不过滤 XML 非法控制字符 | EPUB 的 XHTML 部件会输出裸控制字符，违反 XML 1.0 `Char` 产生式，epubcheck 与阅读器判为文件损坏；HTML 产物同样带上这些字符 | `yuhua-export/src/render/html.rs` |
| 2 | P1 | `is_safe_url` 放行 `data:image/svg+xml` | SVG 可内嵌脚本，构成 XSS 注入通道；HTML 与 EPUB 共用该函数，两个格式都受影响 | `yuhua-export/src/render/html.rs` |
| 3 | P2 | `TrashManager::move_to_trash` 未拒保留目录 | 把 `.trash` 移入回收站会让目标目录建在源目录内部，`rename` 失败后降级为 `copy_recursive`，无限递归至栈溢出（0xc00000fd） | `yuhua-fs/src/trash.rs` |

### 缺陷 1：控制字符未过滤

同一 crate 的 `docx.rs::escape_xml` 早就正确处理了这件事（注释里写明「直接写进 XML 会让 Word 报文件已损坏」），
但 HTML 与 EPUB 复用的是 `escape_html`，它只转义五个实体。
实测探针确认：正文含 `\u{0b}`（从 PDF / 网页粘贴内容的常见残留）时会原样写进产物。

修复：让 `escape_html` 采用与 `escape_xml` 相同的规则丢弃 C0 控制字符，
保留 Tab / LF / CR 这类合法空白。EPUB 复用同一函数，因此一处修复覆盖两个格式。

### 缺陷 2：SVG 数据 URL 放行

白名单原本只判断 `starts_with("data:image/")`，`data:image/svg+xml` 以此前缀通过。
关键在于 **`escape_html` 的实体转义并不能阻止执行** ——
浏览器会在解析 URI 前先做实体解码，把 `&lt;` 还原回 `<`，可执行 SVG 照样成立。
产品定位是「单文件 HTML 可直接双击打开、可发给编辑」，所以这是真实注入面而非理论问题。

修复：改为位图 MIME 精确前缀白名单（png / jpeg / jpg / gif / webp / avif），
并要求前缀后紧跟 `;` 或 `,`，避免 `data:image/pngx...` 这类边界绕过。

### 缺陷 3：回收站可自我嵌套

 `move_to_trash` 只经 `layout.resolve` 校验路径不逃逸工作区，不排除保留目录。
目标是 `.trash` 本身时，`create_dir_all` 会先建出一个位于**源目录内部**的目标目录；
于是 `rename` 必然失败，代码走进降级分支，`copy_recursive` 开始把源目录复制进它自己的子目录，递归无终止。

需要说清楚的是：**当前命令层只传入来自内存 `Document` 的 `manuscript/...` 路径，`UI 无法触发**，
所以这是对外 API 的健壮性缺口，而非当下可利用的漏洞 —— 因此定为 P2。

修复：入口处拒绝保留目录（复用 `WorkspaceLayout::is_reserved_name`）与回收站自身，
并在 `copy_recursive` 内部加固「目标不得是源的后代」，让这条不变量成为函数自身的保证而不是调用者的义务。

### 新增回归测试

| 测试 | 守住的性质 |
| --- | --- |
| `control_characters_are_stripped_from_output` | 控制字符被丢弃，Tab / LF / CR 保留 |
| `svg_data_urls_are_rejected` | SVG 数据 URL（含大小写变体）被拒，位图仍放行 |
| `reserved_paths_cannot_be_trashed` | `.trash` / `.yuhua` 及其子路径不能进回收站 |
| `copy_recursive_rejects_self_nesting` | 复制目标是源的后代时报错，而非递归到栈溢出 |

**修复后实测**：`cargo test --workspace` **825 通过 0 失败**（修复前 821，净增 4 条回归测试）、
`cargo clippy --workspace --all-targets` 零警告、`cargo fmt --check` 合规、前端 1336 个测试仍全绿。

### 审查中确认无问题的部分

原子写（同目录临时文件 / fsync / 回滚 / sweep）、`layout.resolve` 的路径逃逸防护（`..` / 盘符 / UNC 全部拦截）、
备份 20 份轮转上限、`store` 层全部 SQL 使用绑定参数（无注入面）、CRDT 合并的交换 / 结合 / 幂等性、
冲突副本只读不删、命令层错误处理（生产代码无 `unwrap` / `panic`）—— 这些经核查确认无缺陷。

## 五、过程中发现并修复的真实缺陷

这些不是「跑通了」，而是**测试或验证过程中发现产品代码本身有问题**：

| # | 缺陷 | 影响 | 发现方式 |
| --- | --- | --- | --- |
| 1 | 搜两字中文词必然落空 | **检索功能对中文等同于不可用** | 排查集成测试失败 |
| 2 | `Index::rebuild` 不重建卷 | 重建索引触发外键失败 | 单元测试 |
| 3 | 动效并发配额泄漏 | 30 次动效后所有动效永久静默降级 | 单元测试 |
| 4 | 过阻尼弹簧时长严重低估 | 动画中途被截断 | 单元测试 |
| 5 | 临界阻尼包络少算多项式因子 | 动画差 0.8% 被截断 | 单元测试 |
| 6 | Dialog 焦点陷阱静默失效 | **键盘用户 Tab 能跑出弹层** | 组件测试 |
| 7 | Menu 方向键完全无法移动 | 菜单键盘操作不可用 | 组件测试 |
| 8 | `div[tabindex=0]` 永远不可聚焦 | 无原生控件的弹层焦点陷阱失效 | 组件测试 |
| 9 | Select 选中项永远停在第一项 | 下拉选择不可用 | 组件测试 |
| 10 | 云盘同步改 mtime 触发全量重索引 | 性能退化 | 设计时用双闸门规避 |

第 1 条尤其值得记录：**分词器为提升召回在每个 CJK 游程末尾补了一个
单字 token，查询侧却把它当成必要条件**，于是搜「羽化」要求索引里存在
独立的「化」—— 而正文切出的是 `羽化/化写/写作/作`，根本没有「化」。

修复后补了一条**契约测试**：查询串产生的每个 token 都必须在
「正文分词结果的 token 集合」中存在。这条测试能防止同类问题再次出现。

所有偏离都写进了代码注释与 done-list，此处汇总：

**这些偏离都不改变对外行为。**

## 七、需要你决策的事

### 1. PDF 导出（计划书标注的最高风险项）

本轮做了设计与风险拆解，写进 [pdf-spike.md](./pdf-spike.md)，
但**没有做实际验证**。核心问题：

- 首选方案（WebView 打印到 PDF）需要写**三份平台特定 FFI 代码**，
  且要求 WebView 已创建 —— 与「导出不依赖 UI」的设计有冲突
- 备用方案（纯 Rust 渲染）中，Typst 体积通常 >10 MB，
  **会吃掉为内置字体预留的安装包预算**

**需要你决定**：若 macOS/Linux 上首选方案不可行，
是接受安装包变大，还是「Windows 优先做 PDF、其它平台暂缓」？

### 2. 下一轮的优先级

按对「能用」这一目标的影响，我建议的顺序是：

1. **编辑器内核（M4）** —— 写作软件的核心，没有它「打开即写」不成立
2. **统计与检索的前端界面（M6 / M8）** —— 数据层已完备，只差接线
3. **PDF 导出 Spike** —— 单独安排，避免阻塞其余五种格式
4. **字体子集化流水线** —— 阻塞内置字体与安装包体积验收

如果你有不同判断，请告诉我。
