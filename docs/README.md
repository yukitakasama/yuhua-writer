## 🔒 安全性保证

### 代码审查发现并修复的缺陷（3 个）

| 级别 | 缺陷                  | 修复                                   | 回归测试                                                                  |
| ---- | --------------------- | -------------------------------------- | ------------------------------------------------------------------------- |
| P1   | XML 控制字符未过滤    | 采用 `escape_xml` 规则丢弃 C0 控制字符 | `control_characters_are_stripped_from_output`                             |
| P1   | SVG 数据 URL XSS 通道 | 改为位图 MIME 精确白名单               | `svg_data_urls_are_rejected`                                              |
| P2   | 回收站可自我嵌套      | 拒绝保留目录 + 复制自嵌套检查          | `reserved_paths_cannot_be_trashed`, `copy_recursive_rejects_self_nesting` |

### 文件安全机制（均有测试覆盖）

- ✅ 原子写：不留半截文件
- ✅ 轮转备份：5 分钟 / 20 份上限

- ✅ 路径守卫：拒绝逃逸与保留目录
- ✅ 冲突识别：只提示不删除（7 种云盘命名）
- ✅ 索引外置：避免云盘同步冲突
- ✅ 崩溃恢复：启动时清理临时文件

1. **性能验收（M11）** - 2026-10-06 首次完整采集、2026-10-07 复测。可自动化项
   8 项达标（含 M4：查出并修掉一个让空闲 CPU 常驻 44% 单核的装饰动画，
   复测 0.100%）。**M1 / M1b 超标已于 2026-10-10 拍板结案：按现状接受，不重做**
   （用户结论「内存目前可以接受，不需要重做」）。口径按已公布的那份用：M1 =
   进程树**私有内存**之和（禁止用工作集之和，共享页会重复计数），拆成
   M1b（Rust 内核 ≤ 30 MB，实测 44.93 MB → **超标已接受**）与 M1v
   （WebView2 视图层基线 ≤ 200 MB，实测约 158–170 MB，**在预算内**，
   这一项本来就不由本应用决定）；M4 = 单核等价。
   **预算数值一个都没改**，被改掉的只有状态列；若将来要重开这项预算，
   从 `docs/benchmarks.md` 偏差 1 里被终止的那两条实验（WebView2 参数裁剪、
   空白窗口 vs 书架页的对照量法）接着走，不要重新调查。
   还剩 11 项需 GUI 人工采集（M2 M3 M5 M6 M8 P1 P2 P7 P11 与 P4 / P3 应用内段）。
2. **安装包的装机验证（M10）** - Windows NSIS 包 2026-10-07 首次端到端产出，
   并于 2026-10-10 22:03 用含三条丢稿修复的代码重跑（`target/release/bundle/nsis/`
   下 12,238,249 B = 11.67 MiB，P6 达标），但**从未真正安装并运行过**；
   `webviewInstallMode = downloadBootstrapper` 还意味着安装时需联网拉 WebView2。
   macOS / Linux 未验证，发布流水线（T10.6）与实际发布（T10.8）未做。
   **同一批要顺手验掉的**：关闭屏障的**接线本身**（`CloseRequested` →
   `flush-and-close` 事件 → `notify_flush_done` 放行）。jsdom 里 `isTauri()` 恒假，
   自动化只钉住了「收到事件之后」的顺序与 3 秒兜底，事件名两边对不对得上
   只有真机能证明 —— 而它管的是「关窗不要丢最后一段」，属丢稿方向
