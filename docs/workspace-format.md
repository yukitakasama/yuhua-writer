# 工作区格式与云盘同步

## 工作区是什么

**一个工作区就是一个普通文件夹。** 里面没有数据库、没有二进制，
只有 Markdown 文本和少量 JSON 配置。这个设计的目的是：

- 你的稿子永远可以用任何编辑器打开
- 可以放进任何云盘实现多设备同步
- 可以在不安装本软件的机器上完整备份、迁移

## 目录结构

```text
我的小说/                       工作区根目录（你自己选的位置）
├─ .yuhua/                      引擎目录（应用私有）
│  ├─ workspace.json            工作区配置：格式版本、ID、创建时间、卷清单
│  ├─ backup/                   轮转备份快照（纯 .md，保留最近 20 份）
│  ├─ journal/                  崩溃恢复日志
│  └─ stats/                    写作统计（纯 JSON，按月份片）
│     ├─ daily-2026-01.json
│     └─ daily-2026-02.json
├─ manuscript/                  正文（Markdown，唯一真源）
│  ├─ 001-第一卷 风起/
│  │  ├─ 001-第一章 落羽.md
│  │  └─ 002-第二章 山雨.md
│  └─ 002-第二卷 惊蛰/
│     └─ 001-第一章 xxx.md
├─ outline/                     大纲
├─ characters/                  人物设定
├─ worldbuilding/               世界观设定
└─ .trash/                      回收站（保留 30 天）
```

目录名带 `001-` 这样的序号前缀，是为了让**系统文件管理器里的排序
与应用内的排序一致**。即使你完全不用本软件，文件也是有序的。

### 章节目录与笔记

新建工作区和新建章节使用以下 Markdown 布局：

```text
<应用安装目录>/novel/<工作区名称>/
├─ outline/
└─ manuscript/
   └─ <卷目录>/
      └─ <章节目录>/
         ├─ <章节目录>.md
         └─ tips.md        # 可选，用户手动添加的笔记
```

每个章节目录默认只创建与章节目录同名的 `.md` 正文文件。`tips.md` 不参与正文扫描，删除章节时会随章节目录一起移入回收站，因此用户添加的笔记不会丢失。旧版直接放在卷目录下的 Markdown 章节仍可继续读取。

### 卷名存在哪里

**卷的名字与顺序存在 `.yuhua/workspace.json` 的 `volumes` 字段里**，
不是从目录名读出来的：

```json
{
  "formatVersion": 1,
  "workspaceId": "ws_01J8XK2M9P",
  "title": "我的小说",
  "volumes": [
    {
      "id": "vol_01J8XK2M9P",
      "title": "第一卷 风起",
      "sort": 0,
      "dirName": "001-第一卷 风起"
    }
  ]
}
```

这样设计有两个原因：

1. **重命名卷不会改动磁盘目录名。** 如果重命名要去改目录名，云盘与 Git
   会看到「删除一个目录 + 新增一个目录」两个事件，正在同步的其它设备
   可能先看到删除。现在重命名只写一次配置。
2. **目录名只是磁盘上的存放位置，可以和你看到的名字不一致。** 你手工
   把目录改名也不会让卷名丢失 —— 该卷记录里的 `dirName` 仍指向旧目录，
   应用会把卷名与顺序按配置呈现。

**手工改目录名会怎样：** 若目录名与配置里的 `dirName` 对不上，应用会把
它当成一个**新的卷**（名字从目录名推导）。想让某个目录对应到已有卷，
请直接编辑配置里的 `dirName` 字段，或把目录名改回去。

**旧版工作区（配置里没有 `volumes`）：** 第一次用新版本打开时会自动
按目录名推导出卷清单并写回配置，无需你做任何事，卷名与顺序不变。

## 章节文件格式

```markdown
---
id: ch_01J8XK2M9P
title: 第一章 落羽
status: draft
wordGoal: 3000
created: 2026-01-01T09:00:00+08:00
updated: 2026-01-01T21:30:00+08:00
tags: []
---

正文内容写在这里。

可以正常使用 Markdown：

## 二级标题

**粗体**、_斜体_、`行内代码`

> 引用

- 列表项
```

### 关于 Front Matter

文件顶部 `---` 之间的部分是元数据块，是**元数据的真源**。
数据库只是它的缓存。

**可以放心手工编辑**，字段缺失不会导致章节打不开：

| 字段                  | 缺失时的行为                           |
| --------------------- | -------------------------------------- |
| `id`                  | 自动生成一个新的                       |
| `title`               | 从文件名推导（会剥掉 `001-` 序号前缀） |
| `status`              | 默认 `draft`                           |
| `created` / `updated` | 用当前时间                             |

**不认识的字段会被原样保留**，不会因为你用了新版本软件而被吃掉。

### 支持的 Markdown 子集（冻结）

第一阶段明确支持以下语法，导出时各格式都会正确处理：

| 语法                             | 支持                                 |
| -------------------------------- | ------------------------------------ |
| `#` 到 `######` 标题             | 是                                   |
| 段落                             | 是                                   |
| `**粗体**` / `*斜体*`            | 是                                   |
| `> 引用`                         | 是                                   |
| 无序 / 有序列表（嵌套最多 3 层） | 是                                   |
| `---` 分割线                     | 是                                   |
| 行内 `代码`                      | 是                                   |
| 代码块                           | 是                                   |
| 链接、图片                       | 是                                   |
| 表格                             | **否**（导出时降级为纯文本并提示）   |
| 脚注                             | **否**（导出时降级为括号内联并提示） |
| LaTeX 公式                       | **否**（原样保留文本）               |
| 原始 HTML                        | **否**（转义为文本）                 |

不支持的语法**不会被静默丢弃** —— 导出前会提示，导出报告中也会列出。

## 索引库在哪里

**索引库不在工作区里。** 它在系统应用数据目录：

| 平台    | 路径                                                                |
| ------- | ------------------------------------------------------------------- |
| Windows | `%APPDATA%\YuhuaWriter\index\<工作区ID>.sqlite`                     |
| macOS   | `~/Library/Application Support/YuhuaWriter/index/<工作区ID>.sqlite` |
| Linux   | `~/.local/share/YuhuaWriter/index/<工作区ID>.sqlite`                |

### 为什么要这样

SQLite 是二进制文件，且运行时带 `-wal` 和 `-shm` 两个附属文件。
云盘客户端对正在写入的二进制文件做**部分同步**时极易损坏数据库。

而索引本来就是**可以随时重建的缓存** —— 所有内容都能从
Markdown 文件重新生成。把它移出工作区，让工作区保持「纯文本」
这一性质，是云盘同步安全的前提。

**索引损坏怎么办：** 在设置页点「重建索引」，或者直接删掉那个
`.sqlite` 文件重启应用。不会丢任何一个字。

## 数据安全机制

| 机制               | 做什么                                                                          | 解决什么问题                                       |
| ------------------ | ------------------------------------------------------------------------------- | -------------------------------------------------- |
| **原子写**         | 写临时文件 → 刷盘 → 原子替换                                                    | 断电后要么是旧内容、要么是新内容，不会出现半截文件 |
| **防抖保存**       | 停止输入 1.5 秒后保存；连续输入时最长 30 秒必存一次；失焦、切章、关窗前强制保存 | 少写磁盘，同时不丢稿                               |
| **轮转备份**       | 距上次快照超过 5 分钟时把旧版存入 `.yuhua/backup/`，保留最近 20 份              | 误改写可回溯                                       |
| **崩溃日志**       | 保存前写待提交记录，成功后清除                                                  | 崩溃后能提示你检查哪些内容                         |
| **回收站**         | 删除即移到 `.trash/`，保留 30 天                                                | 误删可救                                           |
| **云盘冲突识别**   | 识别冲突副本文件名，提示但不删除                                                | 多设备同步不丢数据                                 |
| **保存前冲突检查** | 保存时比对磁盘上的内容哈希，不一致则**拒绝写入**并提示                          | 不静默覆盖别的设备 / 别的编辑器写的内容            |

## 云盘同步指南

### 怎么用

**把整个工作区文件夹放进云盘同步目录即可。** 软件不需要任何配置。

已验证的同步方式：

- 坚果云、阿里云盘、百度网盘
- OneDrive、Dropbox、Google Drive、iCloud Drive
- Syncthing、局域网共享、U 盘
- Git 仓库

建议把工作区放在**专门为这部作品建的同步文件夹**里，
而不是和其他文件混在一起 —— 便于控制同步范围。

### 能力边界（请务必了解）

**提供的是「最终一致性同步」，不是实时协作。**

| 情况                             | 行为                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| 在 A 机器改一章，B 机器稍后同步  | 正常。B 机器上该章若未在编辑，会自动重载                     |
| 两台机器**同时**改同一章         | 云盘产生冲突副本，软件会识别并提示，**绝不自动删除任何文件** |
| 一台机器在编辑，另一台改了同一章 | 软件提示冲突，**保留你内存里的版本**，不静默覆盖             |

**建议：同一时间只用一台设备编辑。** 这是所有基于云盘的方案
共同的前提，不是本软件的缺陷。

### 发现冲突副本后怎么办

软件会在启动时或同步后提示「发现 N 个冲突文件」，例如：

```text
manuscript/001-第一卷/001-第一章 (冲突副本 2026-01-01).md
```

处理方式：

1. 打开这两个文件对比（_`001-第一章.md` 是当前版本_）
2. 把需要的内容手动合并到主文件
3. 确认无误后，手动删除那个冲突副本

**软件永远不会替你删除冲突副本** —— 那可能包含你在另一台设备上
写的内容。

### 写作统计如何合并

统计文件（`.yuhua/stats/`）也会被同步。合并规则是**单调**的，
因此不会重复计数：

| 数据           | 合并规则                                 |
| -------------- | ---------------------------------------- |
| 每天每章的字数 | **取最大值**（防止两台设备相加导致翻倍） |
| 写作会话       | 按开始时间戳去重后取并集                 |
| 每日目标       | 取最后修改的那一个                       |

**已知局限：** 若在两台设备上**同一天改了同一章**，合并后取较大的
那一次，可能少算。这是为避免翻倍计数的自觉取舍，误差有界。

## 备份建议

虽然软件有多重保护，**定期整体备份**仍然是最可靠的手段：

1. 直接复制整个工作区文件夹到别处（最直观）
2. 用 Git 管理（每次提交都是一个完整快照）
3. 定期压缩打包归档

工作区全是文本，因此压缩率很高，几百章的作品通常只有几 MB。
