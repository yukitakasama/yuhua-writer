# 导出手册

本文说明六种导出格式各自适合什么场景、有什么能力边界，
以及投稿时如何选择。

## 快速对照

| 你要做什么                           | 用哪个格式                            |
| ------------------------------------ | ------------------------------------- |
| 投给网文平台（起点、晋江等）         | **TXT**，多数平台要求纯文本粘贴或上传 |
| 投给出版社 / 编辑，要能批注          | **DOCX**                              |
| 自己打印或做阅读稿                   | **PDF**                               |
| 发给读者看、发在网页上               | **HTML**                              |
| 上架电子书平台（多看、掌阅、Kindle） | **EPUB**                              |
| 归档备份、继续用其它工具编辑         | **Markdown**                          |

## 范围选择

六种格式都支持四种范围：

- **当前章** —— 只导出正在编辑的一章
- **选中章节** —— 在卷章树里多选后导出
- **整卷** —— 导出一整卷
- **整书** —— 导出全部

## 各格式详解

### TXT —— 交稿最通用

**适合：** 网文平台投稿、发给编辑、微信/QQ 传输。

**格式选项：**

| 选项         | 说明                             | 建议                                           |
| ------------ | -------------------------------- | ---------------------------------------------- |
| 换行宽度     | 每行最多多少个字，0 表示不硬换行 | **保持 0**。平台一般会自己排版，硬换行反而添乱 |
| 首行缩进     | 每段开头缩进几个全角空格         | 平台要求缩进时填 2，否则填 0                   |
| 章节标题格式 | 标题行的写法                     | 需与平台要求一致，常见是 `第一章 标题`         |
| 章间分页符   | 每章之间插入分页符               | 一般不需要                                     |

**能力边界：** 粗体、斜体、列表符号在纯文本里无法表达，会被忽略或
转成对应符号。**这是格式本身的限制，不是软件的问题** —— 纯文本
本来就承载不了这些样式。

### Markdown —— 归档与再编辑

**适合：** 备份、换用别的写作工具、放进 Git 管理、投稿给接受
Markdown 的平台。

**特点：**

- **剥离 Front Matter**（那个 `---` 元数据块），只留正文
- 卷作为一级标题，章作为二级标题，层级偏移可配置
- 完整保留所有 Markdown 语法

**为什么剥离 Front Matter：** 元数据是本软件的工作数据
（ID、时间戳），对读者和其它工具都没有意义。需要保留时可在选项中开启。

### HTML —— 网页预览与打印

**适合：** 发给读者阅读、贴到网页、自己打印。

**特点：**

- 生成**单文件** HTML，内置响应式排版样式，双击即可打开
- 正文最大宽度 720px、行高 1.8，为长文阅读优化
- 可选**内嵌字体**（Base64），使单文件离线也能保真显示中文字体

**关于内嵌字体：** 开启后会显著增大文件体积（可能到几 MB），
但能保证在任何设备上显示效果一致。发给自己存档建议开，
发到网页上建议关。

### DOCX —— 投稿与编辑

**适合：** 投给出版社、需要编辑批注、需要对方用 Word 修改。

**特点：**

- 符合 OOXML 标准，**Word 与 WPS 都能正常打开**
- 内置标题样式（Heading1/2/3），可用 Word 的导航窗格跳转
- 显式声明中文字体（跟随你的字体设置）
- 每章自动分页

**结构约定：** 卷作为一级标题，章作为二级标题，不单独为卷分页。

**明确不做：** 目录域、交叉引用、批注、文本框、图片环绕。
这些属于排版软件的职责，不是写作软件第一阶段的范围。

### PDF —— 打印与阅读稿

**适合：** 自己打印、做阅读稿、需要确定排版效果的场合。

**特点：**

- **中文字体正确嵌入**，文本可搜索、可复制
- 卷首分页

**实现方式说明：** PDF 通过系统 WebView 的「打印到 PDF」能力生成。
好处是所见即所得、零额外依赖；代价是排版细节由渲染器决定，
定制空间有限。

**明确不做：** 书签目录、页眉页脚、页码样式的深度定制。

### EPUB —— 电子书

**适合：** 上架电子书平台、发给用阅读器的读者。

**特点：**

- 标准 **EPUB 3**，含导航目录（nav）
- 每章一个 XHTML 文件
- 元数据可填：书名、语言、作者

**关于内嵌字体：** 第一阶段**默认不内嵌**。原因是各阅读器对
内嵌字体的支持差异很大，部分阅读器会忽略它，反而造成
「有的设备一个样、有的设备另一个样」。作为可选项提供。

**兼容性：** 导出产物会通过 `epubcheck` 校验，保证零 error。

## 导出时的内容提示

导出前后，软件会明确告诉你哪些内容被降级处理了。

**支持的 Markdown 子集：**

| 语法                        | 导出行为                         |
| --------------------------- | -------------------------------- |
| 标题、段落、粗体、斜体      | 各格式原生支持                   |
| 引用、列表（嵌套最多 3 层） | 原生支持                         |
| 分割线、行内代码、代码块    | 原生支持                         |
| 链接                        | 保留                             |
| 图片                        | TXT 丢弃；其它格式内嵌或保留链接 |

**不支持（会降级并提示）：**

| 语法       | 降级方式                         |
| ---------- | -------------------------------- |
| 表格       | 转为纯文本，保留内容但对齐会丢失 |
| 脚注       | 转为括号内联                     |
| LaTeX 公式 | 原样保留为文本                   |
| 原始 HTML  | 转义为文本（防止破坏文档结构）   |

**重要：** 降级内容**绝不会静默丢弃**。导出前的提示与导出后的
报告都会列出「第几章包含表格，已降级为纯文本」这样的信息。
如果你依赖这些语法，请在导出后检查产物。

## 导出预设

每个格式会**独立记住你上次的选项**。例如你可以让 TXT 永远保持
「不缩进、不硬换行」，让 DOCX 永远用宋体 —— 设置一次即可。

## 常见问题

**Q：导出的 TXT 里粗体没了**

A：纯文本格式无法表达粗体。需要保留样式请用 DOCX 或 HTML。

**Q：导出的 EPUB 在某些阅读器里显示效果不同**

A：这是阅读器对 CSS 与字体处理的差异。我们遵循标准并保证通过
`epubcheck` 校验，但无法控制每个阅读器的渲染细节。
若排版一致性很重要，建议用 PDF。

**Q：PDF 里的中文能复制吗**

A：能。PDF 导出时嵌入了字体子集，文本是可搜索、可复制、
可正常参与检索的 —— 这是硬性验收标准，不是「尽力而为」。

**Q：导出 100 万字的小说，软件会不会卡死**

A：不会。导出是**按章流式处理**的，内存峰值与书籍总字数无关。
导出 100 万字 / 300 章的整书，内存峰值目标是不超过 120 MB。

**Q：导出过程中能取消吗**

A：能。任意时刻取消都会清理掉未完成的临时文件，不会留下半个产物。

**Q：为什么导出的是临时文件再改名**

A：为了保证**原子产出** —— 导出失败时你看到的要么是完整的旧文件、
要么是完整的新文件，绝不会出现一个写到一半的残缺文档。
