# 字体切换不闪动验证（T1.12）

> 验收要求：「字体切换不闪动验证：测量重排耗时与掉帧」。
> 配套硬约束（计划书 5.4）：「字体切换不得触发整页重排动画：只更新 CSS 变量」。

本文说明**怎么验证**这件事。自动化部分已经写进测试，人工部分给出可复现的操作步骤。

---

## 1. 闪动的两个成因

先说清楚要防的是什么，否则「不闪动」是一句没有内容的话。

| 成因 | 表现 | 消除手段 |
| --- | --- | --- |
| **FOUT**（Flash of Unstyled Text） | 切换字体后先用回退字体画一帧，字形下载完再跳成内置字体，文字宽度突变 | 切换 `--font-*` **之前**等 `FontFace` 就绪；等待期间保持旧字体（旧字体已是可用字形，因此没有跳变） |
| **大面积样式重算** | 给每个文本节点写内联 `font-family`，命中节点数与文档长度成正比，长章节明显卡顿 | 只写 `:root` 上的自定义属性，样式重算是一次性的 |

还有一类**不是问题**的变化：字号 / 行距 / 宽度改变必然导致文本重新排布。
那是用户正在调排版，属于预期效果。要保证的只是它**不被动画化** ——
自定义属性不是可过渡属性，这一点天然成立（前提是没有人给它加 `@property`）。

## 2. 自动化验证（`pnpm test`）

测试文件：`src/features/settings/no-flicker.test.ts`（15 个用例）。

jsdom **没有布局引擎**（`getBoundingClientRect` 恒返回 0，也没有帧调度），
所以真帧率在单测里测不出来。假装测出来只会产出「看起来严格、实际恒过」的测试。
因此自动化部分改用**可判定的结构性断言**，每条对应上表里的一个成因：

| 用例 | 断言 | 对应的成因 |
| --- | --- | --- |
| 切换字体只写 `:root` 上的自定义属性 | 根元素 `style.fontFamily === ""` | 大面积重算 |
| 字号 / 行距 / 宽度只走自定义属性 | `style.fontSize / width === ""` | 大面积重算 |
| 写入的属性名全部以 `--` 开头 | 遍历 `typographyVariables()` 的键 | 防止误写内联样式 |
| CSS 里没有 `@property` 声明 | 扫描 `tokens.css` / `app.css` / `settings.css` | 防止自定义属性变成可过渡 |
| CSS 的 `transition` 不指向字体相关属性 | 抽出所有 `transition(-property)` 声明做匹配 | 防止意外触发过渡动画 |
| `preload` 在字形就绪前保持 pending | 用可控的 `FontFace` 替身卡住 `load()` | FOUT |
| 三作用域共用字族只加载一次 | `loader.size === 1` | 三次字形解析 → 三次重绘 |
| 加载失败时 `preload` 仍 resolve | 真实宿主在 jsdom 下必然失败 | 失败不该阻塞排版应用 |
| 连续改字号只留最后一次的值 | 循环写入后读回终值 | 确认无中间态残留 |

跑法：

```bash
pnpm test src/features/settings/no-flicker.test.ts
```

## 3. 人工验证：测量重排耗时与掉帧

自动化测不到的部分在这里补。需要打包产物或 `pnpm tauri:dev`，用 WebView2 的 DevTools。

### 3.1 准备

1. 打开一个**足够长**的章节（建议 ≥ 5000 字，短文档暴露不出问题）；
2. 打开 DevTools → **Performance**；
3. 勾选 **Screenshots**（这样能直接看到有没有视觉跳变）；
4. CPU 降速设为 **4×**（计划书的目标机器是中低端笔记本，不降速测不出差异）。

### 3.2 录制步骤

1. 点 **Record**；
2. 切到设置 → 字体 → 正文，把字体族从「宋体」改成「楷体」；
3. 再把字号从 17 拖到 22，宽度从 720 拖到 960；
4. 点 **Stop**。

### 3.3 看什么

| 指标 | 合格标准 | 在 Performance 面板的哪里看 |
| --- | --- | --- |
| **主线程总耗时** | 单次字体切换 ≤ 50 ms；单次拖滑块 ≤ 16 ms | 顶部 Summary 的 **Scripting + Rendering** |
| **掉帧** | 任意 1 秒内掉帧 ≤ 2（计划书指标 P2） | **Frames** 轨道上的红色斜纹帧 |
| **Layout 次数** | 字体切换一次；拖滑块时每次输入一次 | 火焰图里的 **Layout** 块数量 |
| **Recalculate Style** | 字体切换只有**一次**大块（在 `:root` 上） | 火焰图；若出现几十个小块则是命中了多个节点 |
| **视觉** | Screenshots 轨道上没有「字体先跳一变」的帧 | 逐帧看切换瞬间 |

### 3.4 反例对照（用来确认测量方法本身有效）

临时把 `src/design/fonts/apply.ts` 的 `applyTypography` 改成逐个文本节点写内联样式，
重跑一遍上面的录制。正常应该看到：

- **Recalculate Style** 出现大量小块；
- **Layout** 次数明显上升；
- 4× 降速下能观察到掉帧。

如果反例测不出差异，说明文档太短或降速不够，测量方法本身需要调整 ——
**先证明方法能测出坏情况，再相信它测出的好结果**。

## 4. 内存验证（指标 M5 / M6）

字体常驻内存是同一套加载策略的另一面，顺带记录测法：

| 指标 | 标准 | 测法 |
| --- | --- | --- |
| M5 | 同时加载的内置字族 ≤ 2 个，常驻内存 ≤ 24 MB | DevTools → Memory → 堆快照，对比切换前后的 `FontFace` 对象数与 `ArrayBuffer` 总量 |
| M6 | 切换字族 60 秒后前一字族可被回收，残留 ≤ 4 MB | 切三次字族（宋 → 楷 → 系统宋），等 60 秒，手动 GC 后再拍快照 |

`FontLoader` 的 LRU 上限为 2（`MAX_LOADED_FAMILIES`），超出时调用
`document.fonts.delete()` —— 只从常驻表移除而不调 `delete` 的话，
字形缓存不会被释放，M6 就无从谈起。这一点由
`src/design/fonts/fonts.test.ts` 的「淘汰时调用 document.fonts.delete」用例守住。

## 5. 已知限制

- **jsdom 无布局**：所有涉及真实像素与帧率的断言都只能在人工步骤里做；
- **首次加载 vs 后续切换**：本文测的是**切换**。首次加载内置字体受
  指标 P7（首屏可读 ≤ 120 ms）约束，属于启动性能，不在 T1.12 范围内；
- **字体文件缺失时**：`pnpm fonts:fetch` 未跑过时字族加载失败，
  CSS 回退链接管，界面依然可读，此时不存在「闪动」问题（因为根本没有切换）。
